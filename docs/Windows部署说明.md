# 康晋电气手势控制平台 Windows 部署说明

交付版本 1.0.0　发布日期 2026 年 11 月 23 日

本文面向部署与维护人员。推荐使用 Windows 运行包，解压后即可启动；完整源码另行提供，方便维护、重新安装依赖和继续开发。

## 1 部署条件与快速启动

运行包内置 Python 3.12 x64、生产依赖、两个识别模型、企业宣传片和当前已保存的工作流配置。无须安装 Python、Node.js、Git 或独立 FFmpeg，也无须首次联网下载模型。

| 项目 | 条件 |
| --- | --- |
| 操作系统 | Windows 10 或 Windows 11 64 位 x64 |
| 浏览器 | Microsoft Edge 或 Google Chrome |
| 网络 | 电脑能够访问摄像头的 RTSP 地址 |
| 磁盘 | 建议预留 4 GB，容纳解压、日志及备份 |
| 显示 | 已核对 1920×1080 与 1366×768 布局 |

1. 将 `GestureControl-Windows-x64-1.0.0.zip` 完整解压到可写目录，例如 `D:\GestureControl`。不要直接在压缩软件内运行，也不要放到需要管理员写入权限的 Program Files。
2. 双击 `CHECK.cmd`。看到 `CHECK PASSED` 表示依赖、模型、宣传片及模型初始化检查通过。该检查使用空白测试帧，不连接真实摄像头。
3. 双击 `START.cmd`。保持启动窗口开启，浏览器会在服务就绪后打开宣传片首页。
4. 点击“开始播放”，再从右上角“管理后台”进入设置，连接 RTSP 摄像头。

默认网址为 `http://127.0.0.1:8000`。端口被占用时会向后寻找空闲端口，以启动窗口显示的网址为准。服务只监听本机，不需要开放入站端口。停止服务时，在启动窗口按 Ctrl+C，等待程序退出。

## 2 文件结构与运行方式

| 路径 | 用途 |
| --- | --- |
| START.cmd | 启动服务并打开浏览器 |
| CHECK.cmd | 检查依赖与真实模型加载 |
| BACKUP.cmd | 备份已保存配置 |
| runtime | 随包 Python 与依赖，整体保留 |
| app 与 web | 后端与前端完整源码 |
| models | 手势与人体识别模型 |
| media | 企业宣传片及登记的视频素材 |
| data/identities.sqlite3 | 工作流、网页目录、版本记录及设置 |
| docs | 部署说明与操作手册 |
| logs | 启动后生成的滚动运行日志 |

首次启动会从 `.env.example` 创建 `.env`，默认 AI 密钥为空。运行包不包含开发机的私有 `.env`、摄像头凭证、识别临时记录或开发日志。交付时保存的工作流、启用状态、历史版本和页面配置随数据库快照保留。

同一份解压目录重复启动时，会提示该实例已运行并打印原网址。不要为了打开后台重复启动服务器；使用大屏“管理后台”或后台导航即可。不同解压目录可以各自运行，但会使用不同端口及各自的数据。

如需指定起始端口，打开 PowerShell 并进入解压目录：

```powershell
.\START.cmd --port 8100
```

只启动服务而不自动打开浏览器：

```powershell
.\START.cmd --no-browser
```

部署前可校验应用、运行环境、模型与素材的完整性：

```powershell
.\runtime\python.exe -I -X utf8 launcher.py --verify
```

文件校验会跳过运行中会改变的数据库。修改源码或替换宣传片后，原交付清单中的对应校验值会失效，这是文件变更的正常结果。

## 3 摄像头与可选功能配置

摄像头须启用 RTSP，电脑与摄像头之间的网络、账号和密码须可用。设置页输入设备厂商提供的 `rtsp://` 或 `rtsps://` 地址，再点击“连接摄像头”。地址只保留于本次运行内存，连接后输入框会清空；服务重启后需要重新输入。

优先使用摄像头的 H.264 子码流。若预览花屏或延迟较大，可在摄像头侧试用 720p 或 1080p、15～20 FPS，关闭 H.265+ 等智能编码，再核对实际画质和识别距离。不要把某一种编码参数当成所有摄像头都适用的固定值。

### AI 工作流生成

普通编辑、保存、校验、模拟和本地宣传片不需要互联网。在“工作流 → AI 生成”中配置服务商提供的 API Key、Base URL、模型名称和协议，先测试连接，再保存。AI 功能需要联网及有效服务账户；上传文档正文会发送给所配置的服务商。密钥保存于本机 `.env`，不会随本次交付提供。

### 外部网页

网页管理可登记外部 HTTPS 地址。外部页面需要相应网络连接；站点是否允许嵌入还受其 iframe 安全策略约束。地址格式校验通过不代表嵌入已成功，须在目标电脑上实际打开检查。本地页面动作只适用于支持本系统页面桥协议的页面。

### 可选 PowerPoint 控制

Windows 运行包包含 pywin32；还需目标电脑安装 Microsoft PowerPoint，并完成首次启动与授权。将可信 PPT 文件固定存放，再编辑 `app/settings.py` 的登记配置：

```python
PRESENTATION_DECKS = {
    "company-deck": {
        "title": "公司介绍",
        "path": r"D:\Showroom\company.pptx",
    },
}
```

保存后重启服务，工作流 PPT 节点中才会出现该文稿。PPT 使用本机绝对路径，迁移电脑时须更新登记；包内不含 PowerPoint 软件，也未附带演示文稿。真实放映需在目标电脑验证。

## 4 备份 升级与恢复

双击 `BACKUP.cmd`，程序会在 `backups` 目录生成带时间的 ZIP。数据库采用 SQLite 在线备份，可在运行时取得一致快照。备份包含数据库、存在时的 `.env` 和 `app/settings.py`；不包含宣传片、PPT 文件及浏览器内的指针校准偏好。

备份中的 `.env` 可能包含 API Key，应作为本地配置妥善保管。宣传片、其他媒体和 PPT 请另行备份。

升级或迁移时按以下顺序操作：

1. 运行备份，记录旧启动窗口的网址和已登记素材位置。
2. 在旧服务窗口按 Ctrl+C，等待退出；关闭旧大屏和后台窗口。
3. 将新版本解压到新目录，保留旧目录作为回退副本。
4. 复制备份中的 `data/identities.sqlite3` 和需要保留的 `.env` 到新目录。旧数据库必须在服务停止后替换。
5. 对照新版本修改 `app/settings.py` 中的媒体与 PPT 配置；不要直接覆盖整个新源码文件，以免丢失新版本配置。
6. 另行迁移新增媒体及 PPT，运行检查，再启动服务并核对工作流与页面目录。

如果选择手动复制数据库，应先停止服务，确认旧进程已经退出。不要在运行时只复制 SQLite 主文件而漏掉未合并的 WAL 数据。

浏览器校准与镜像偏好按浏览器和网站地址保存。更换浏览器、端口或电脑后，需在高级工具中重新设置。主控锁定属于实时状态，不随数据库备份恢复。

## 5 从源码部署

源码包保留工程、测试与配置快照，但不重复包含大型运行环境、模型和宣传片。安装 64 位 CPython 3.10～3.12；若按锁定依赖重建，使用 Python 3.12 x64。进入源码目录后运行：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\setup.ps1
.\run.ps1
```

源码首次安装需联网下载依赖与模型，并将宣传片复制到 `media/company-promo.mp4`。可从 Windows 运行包复制同名媒体及模型。`requirements-lock.txt` 记录本次 Windows 运行包的完整生产版本；基础安装依赖见 `requirements.txt`。源码环境若使用 PPT，另安装 pywin32。源码启动脚本只打印网址，需要手动打开浏览器。

## 6 常见部署问题

**双击没有正常启动。** 确认已完整解压，`runtime/python.exe` 存在，目录可写；从 PowerShell 执行 `START.cmd` 查看完整提示。若系统拦截来自下载文件的运行，按所在单位的终端管理规则处理，不要关闭安全软件。

**DLL 或模型加载失败。** 先运行 `CHECK.cmd`。若提示文件缺失，重新解压完整运行包；若提示缺少 Microsoft Visual C++ 运行库，在目标电脑安装微软官方 x64 Visual C++ Redistributable 后重试。优先使用短英文路径排除路径兼容问题。

**浏览器打不开或出现重复展示窗口提示。** 使用当前启动窗口打印的网址；同一实例只保留一个动作执行大屏。后台用“打开大屏”复用窗口，允许本网站弹出窗口；意外多开的展示页可关闭后返回原大屏。

**RTSP 连接失败或花屏。** 先检查地址、账号、设备 RTSP 开关及网络。可用 VLC 验证同一地址；VLC 也异常时，先排查摄像头。诊断报告和日志不得包含摄像头密码；向维护人员提供时应再次确认内容。

**模型自检通过但识别效果不稳定。** 自检只验证运行环境和空白帧处理，不代表实际摄像头验收。调整摄像头视角、光照、码流及人员距离，让双肩和手部清晰进入画面，再按操作手册进行比耶锁定与多人测试。

## 7 交付与现场验收

交付 ZIP 的 SHA-256 见同目录 `SHA256SUMS.txt`；内部文件清单见 `RELEASE-MANIFEST.json`，环境与配置数量见 `RELEASE.json`。可在 PowerShell 用 `Get-FileHash 文件名 -Algorithm SHA256` 核对 ZIP。

现场检查：启动与宣传片声音、RTSP 预览、比耶锁定、多人隔离、手势执行、页面切换、后台窗口复用、断线重连后的重新锁定，以及目标电脑上的外部网页和可选 PPT。先做单人验证，再做遮挡和多人交叉；建议完成一次持续运行观察。自动化回归和模型自检结果见随包验收记录，不能替代现场摄像头验收。

维护资料：`README.md`、`WORKFLOWS.md`、`MODEL_SOURCES.md`、`THIRD_PARTY_NOTICES.md`，以及 `tests` 与 `scripts` 目录。

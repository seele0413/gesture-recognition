# 康晋电气大屏宣传片与手势控制

本机运行的 RTSP 手势控制展示页。首页以康晋电气宣传片为主画面，摄像头画面显示在右上角；连接地址、人体轨迹和手势映射放在独立设置页，不影响大屏展示。

## 环境与安装

- Windows 10/11 64 位
- Python 3.11 64 位（推荐）或 3.12 64 位；不支持 Python 3.14
- 可访问的 RTSP 摄像头地址
- 首次安装需要联网安装依赖并下载 MediaPipe 模型；RTSP 解码使用 PyAV/FFmpeg 库并在进程内运行

在 PowerShell 中进入项目目录后运行：

~~~powershell
Set-ExecutionPolicy -Scope Process Bypass
.\setup.ps1
.\run.ps1
~~~

Python Launcher 找不到 Python 3.11/3.12 时，可指定解释器：

~~~powershell
.\setup.ps1 -PythonPath "C:\Python311\python.exe"
~~~

服务仅绑定本机 127.0.0.1。run.ps1 默认使用 8000 端口，若该端口已占用会自动选择下一个空闲端口，并在终端打印实际地址；停止服务按 Ctrl+C。项目使用 Python 原生提供的页面，不需要 Node.js。

## 宣传片文件

本地宣传片路径为 media/company-promo.mp4，浏览器通过支持 HTTP Range 的 /media/promo.mp4 分段读取。原始 4K 文件不转码。视频因体积较大已加入 Git 忽略规则，不会随 Git 提交；迁移整个项目文件夹时应一并保留 media/company-promo.mp4。若从 Git 单独克隆项目，请将宣传片复制到该路径，否则首页会提示视频文件不可用。

## 使用

1. 在首页点击“开始播放”，视频随后带声音循环播放。视频底部提供浏览器原生播放器控件，可用鼠标播放/暂停、拖动进度、调节音量、静音和全屏。播放器按完整 16:9 画面显示，不裁切画面中的字幕。
2. 点击右上角齿轮进入设置页；设置页在当前标签打开，使用浏览器返回或“返回大屏”回到主页。填写 rtsp:// 或 rtsps:// 摄像头地址并连接；连接后设置页显示实时画面与人体轨迹，主页右上角同步显示摄像头。
3. 主控人面向摄像头做 OK 手势：拇指与食指尖形成闭环，其余三指伸展。至少连续 5 帧且唯一关联到一个人体轨迹后锁定。
4. 锁定后只处理该人体轨迹的手势。关联不明确或轨迹丢失时立即暂停控制；2 秒内可靠匹配会恢复，超过 2 秒自动解锁。可在设置页手动解除主控。
5. 手势须连续稳定至少 3 帧、置信度不低于 0.7 才触发；相同动作有 800 ms 冷却。设置页可修改映射并保存。
6. 浏览器控制台输出 [gesture-control] 事件对象，包含临时 track_id、手势类别、置信度、左右手、时间戳、动作和 21 个归一化手部关键点。

默认播放器映射：

| 手势 | 动作 |
| --- | --- |
| 张开手掌 | 播放 / 暂停 |
| 竖拇指 | 音量增加 |
| 拇指向下 | 音量降低 |
| V 字手势 | 静音切换 |
| 握拳、食指向上、我爱你手势 | 不执行 |

全屏只能由首页上的全屏按钮触发，这是浏览器对全屏 API 的安全限制；WebSocket 手势事件不能直接请求全屏。

## 本机接口

- GET /：大屏宣传片主页。
- GET /settings：RTSP 与手势映射设置页。
- GET /media/promo.mp4：宣传片，支持 HTTP Range 分段读取和 seek。
- GET /video.mjpg：处理后的摄像头 MJPEG 画面。
- GET /api/status：流状态、人体轨迹及主控状态。
- POST /api/stream/start、POST /api/stream/stop：启动或停止单路 RTSP。
- POST /api/controller/unlock：解除当前主控。
- GET /api/mappings、PUT /api/mappings：读取或保存手势动作映射。
- /ws/events：推送主控状态与稳定手势事件。

## 数据与隐私

- 服务默认只绑定 127.0.0.1，不开放局域网或公网访问。
- RTSP 地址和凭证只交给当前运行进程处理，不保存到数据库或日志；设置页连接成功后会清空地址输入框。
- SQLite 仅存手势映射和当前会话的锁定状态、稳定手势摘要。视频与逐帧跟踪状态不持久化；服务启动、停止流或新建流会清理临时记录。
- 不使用人脸识别或外观重识别。
- 从旧版本升级时，原始“切换开关”“数值加/减”“重置”映射会迁移为播放/暂停、音量增/减和不执行；旧版默认映射中的 V 字手势升级为静音切换。

## 测试

~~~powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
~~~

自动测试覆盖手势门槛、旧映射迁移、API 页面隔离、宣传片 Range 响应、人体轨迹及替身视频流。真实摄像头、多人的遮挡恢复仍需在目标 RTSP 画面中验收。

## 模型许可与排查

MediaPipe 模型来源和 SHA-256 清单见 MODEL_SOURCES.md。模型由安装脚本下载，不随源码提交。缺少模型时重新运行 .\setup.ps1。无法连接 RTSP 时，检查摄像头地址、账号密码、网络路由以及摄像头 RTSP 是否已启用。

RTSP 花屏定位工具：在 PowerShell 中切换到项目目录，先运行 `git fetch origin` 和 `git switch fix/rtsp-corrupt-frames-camera-pip`，再执行 `.\.venv\Scripts\python.exe scripts\diagnose_rtsp.py --frames 120 --samples 8`。工具会隐藏输入 RTSP 地址，不会把地址或凭证写入报告；会保存 PyAV 原始 BGR PNG、JPEG 编码再解码后的 PNG，以及包含 FFmpeg 版本、编码格式、像素格式、帧 plane 步长、NumPy strides、连续性和各阶段耗时的 `diagnostics/rtsp_时间戳/report.json`。确认原始解码正常后，再执行同一命令并增加 `--with-vision`，额外保存 MediaPipe 处理后的图像，以区分解码、视觉处理和 JPEG 编码问题。可选 `--discard-corrupt` 用于比较 FFmpeg 损坏包丢弃开关；默认保持原 main 分支的 RTSP 解码选项。诊断图片和报告只保存在本机，已加入 Git 忽略规则。

摄像头预览花屏时，先用 VLC 打开同一个 RTSP 地址：若 VLC 也花屏，优先在摄像头端切换为 H.264，关闭 H.265+/智能编码/SVC，并尝试使用 720p 或 1080p、15～20 FPS 的子码流；关键帧间隔建议设为 1～2 秒。若 VLC 正常而本项目花屏，请保留摄像头编码、分辨率和帧率信息用于进一步排查。项目使用 PyAV/FFmpeg 在 Python 进程内通过 TCP 解码 RTSP，启用损坏数据包丢弃，并跳过 FFmpeg 标记损坏或无法转换的帧。单帧视觉推理异常会被跳过；连续 3 帧处理失败时，系统会重新初始化解码器和识别模型。地址打不开、连续坏帧或读取超时会按 1、2、4、8、10 秒间隔重连；断线立即暂停控制，恢复后建立新的跟踪会话，必须重新做 OK 手势。状态接口提供当前帧序号、最后一帧时间、帧新鲜度、解码器名称和重连计数。
解码与视觉推理使用独立线程：解码线程持续读取 RTSP，容量为 1 的队列只保留最新未处理帧；当推理速度低于摄像头帧率时主动丢弃过期帧，避免旧帧排队造成延迟持续增长。设置页同时显示最近一次视觉推理耗时和 JPEG 编码耗时、帧进入推理前的队列等待时间和累计丢弃帧数。该机制优先保证实时性，不替代对原始 PNG 的视觉检查。

宣传片主页的摄像头画中画以 `/api/status` 的 `frame_fresh` 作为显示依据，不再依赖持续打开的 multipart MJPEG 图片触发浏览器 `load` 事件或提供 intrinsic size；浏览器可能不会按普通静态图片的方式派发这些信号。MJPEG 每个 JPEG part 显式带 `Content-Length`，并设置 `X-Accel-Buffering: no`，降低分帧解析和代理缓冲风险。设置页视频下方会显示人体轨迹、检测到的手、MediaPipe 手势类别和置信度、OK 几何失败原因、关联到的人体轨迹、锁定帧进度及普通手势动作/未触发原因。手势骨架叠加在摄像头画面上。人体手腕关联不唯一时不会退回人体框猜测；只有没有有效手腕候选时，才允许使用唯一命中人体框的辅助关联。半身画面要求双肩都清晰可见；髋部在画面外不再阻止人体跟踪。

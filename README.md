# 康晋电气大屏宣传片与手势控制

本机运行的 RTSP 手势控制展示系统。首页是常驻 Display Shell，通过同源 iframe 加载登记的本地展示主页；默认主页为康晋电气宣传片，后续可通过工作流切换智能制造和产品中心。连接地址、人体轨迹和手势映射放在独立设置页，不影响大屏展示。

## Windows 交付包

交付运行包包含独立 Python 3.12 x64、生产依赖、MediaPipe 模型、企业宣传片和清理过临时记录的配置快照。完整解压后双击 `CHECK.cmd` 自检，再双击 `START.cmd` 启动；`BACKUP.cmd` 可备份数据库和本机配置。运行包不需要预装 Python、Node.js、Git 或独立 FFmpeg，首次启动不需要联网安装依赖；AI、外部网页和摄像头仍需要各自的网络与服务条件。

部署、备份与源码安装见 [Windows 部署说明](docs/Windows部署说明.md)，现场操作见 [操作手册](docs/操作手册.md)。交付包的 `docs` 目录同时包含 Word 和 PDF 文档。维护人员可用 `scripts/build_windows_release.py` 从已验证的 Windows x64 Python 3.12 环境重建；准确依赖与组成分别见包内 `requirements-lock.txt`、`RELEASE.json` 和 `RELEASE-MANIFEST.json`。

## 环境与安装

- Windows 10/11 64 位
- 64 位 CPython 3.10、3.11 或 3.12；当前锁定的 NumPy/MediaPipe 组合不支持 Python 3.13/3.14
- 可访问的 RTSP 摄像头地址
- 首次安装需要联网安装依赖并下载 MediaPipe 模型；RTSP 解码使用 PyAV/FFmpeg 库并在进程内运行

在 PowerShell 中进入项目目录后运行：

~~~powershell
Set-ExecutionPolicy -Scope Process Bypass
.\setup.ps1
.\run.ps1
~~~

Python Launcher 找不到兼容解释器时，可指定已安装的解释器：

~~~powershell
.\setup.ps1 -PythonPath "C:\Python311\python.exe"
~~~

服务仅绑定本机 127.0.0.1。run.ps1 默认使用 8000 端口，若该端口已占用会自动选择下一个空闲端口，并在终端打印实际地址；停止服务按 Ctrl+C。项目使用 Python 原生提供的页面，不需要 Node.js。

## 宣传片文件

本地宣传片路径为 media/company-promo.mp4，浏览器通过支持 HTTP Range 的 /media/promo.mp4 分段读取。原始 4K 文件不转码。视频因体积较大已加入 Git 忽略规则，不会随 Git 提交；迁移整个项目文件夹时应一并保留 media/company-promo.mp4。若从 Git 单独克隆项目，请将宣传片复制到该路径，否则首页会提示视频文件不可用。

## 使用

1. 首页 Display Shell 默认加载企业宣传片页面；在宣传片页点击“开始播放”，视频随后带声音循环播放。视频底部提供浏览器原生播放器控件，可用鼠标播放/暂停、拖动进度、调节音量、静音和全屏。播放器按完整 16:9 画面显示，不裁切画面中的字幕。
2. 点击大屏右上角“管理后台”打开独立管理窗口；再次点击会聚焦已有后台，保留当前页面和未保存编辑，大屏持续运行。切换到其他展示页面后管理入口仍可使用。后台“打开大屏”优先聚焦已有大屏，首次使用时创建窗口；若浏览器拦截，请允许本网站弹出窗口。在设置页填写 rtsp:// 或 rtsps:// 摄像头地址并连接。摄像头及主控状态在设置页查看，工作流运行情况在底部运行记录查看；设置、网页管理和工作流在同一后台窗口内导航。
3. 主控人面向摄像头做比耶（V）手势：食指和中指伸展、无名指和小指弯曲。最近 5 帧中至少 2 帧识别成功，且始终唯一关联到同一个人体轨迹后锁定；短暂漏检可容忍，但多人候选或关联歧义不会锁定。未锁定时，手部识别最高使用 1600px 输入宽度；锁定后恢复 960px 常规输入，以兼顾远距离锁定能力和后续控制延迟。
4. 锁定后只处理当前主控人体轨迹的手势。系统会记录已关联到主控的手部轨迹；人体轨迹短暂漏检时进入 `suspect`（默认容错 650 ms），只有左右手标识、手腕连续运动和掌宽变化通过唯一匹配时，才允许原主控继续手势或指针操作；无法唯一匹配时暂停操作，不会接受其他人的手。持续不可见后进入 `reacquiring`，立即释放指针并取消当前工作流，再尝试在 3.5 秒恢复窗口内找回原 Track ID。重新出现同一 Track ID 后恢复 `locked`，不要求重新做比耶；超时才自动解锁。手部轨迹仅用于短时运动连续性判断，不是生物身份认证。每次锁定会生成独立 `controller_id`，与临时 `track_id` 分离。可在设置页手动解除主控。
5. 锁定后的普通手势须连续稳定至少 3 帧、分类置信度不低于设置门槛才触发；默认门槛为 0.60，可在设置页按 0.05 步长调整至 0.50～0.90，修改后立即应用并持久化；相同动作仍有 800 ms 冷却。该置信度滑块不影响比耶主控锁定。手势动作在工作流页面配置，也可从网页管理的“配置手势”进入对应页面；全局回退映射会单独标注。
6. 工作流顶部显示适用页面、启动方式、保存和启用状态。适用页面决定“在哪里做手势才生效”，页面切换动作决定“执行后去哪里”。修改后保存，再启用；切换流程、应用 AI 草稿或离开页面时，对未保存修改提供“保存后继续 / 放弃修改 / 取消”。刷新和关闭使用浏览器原生提醒。停用直接作用于已保存流程，不会强制保存未完成的编辑；已启用流程的未保存修改不影响当前运行版本。
7. 设置页原有手势事件列表和浏览器控制台保留识别结果；控制台输出 [gesture-control] 完整事件对象，包括人员轨迹、手势、置信度、左右手、时间、动作和 21 个关键点。工作流底部“运行记录”默认折叠，展开后可查看执行及模拟结果、步骤与错误。指针、镜像、校准和诊断位于画布“高级工具”；指针模式开启时，画布内提供关闭提示。

工作流采用左侧“工作流 / 节点”页签与大画布布局。工作流列表支持名称、描述、手势及页面搜索，并显示所有触发类型；节点按逻辑、网页、视频、PPT 分类，支持搜索、点击添加与拖入画布。单击节点打开右侧参数抽屉，拖拽调整位置。名称、保存状态和核心操作放在画布上方；描述、复制、删除和独立校验位于“更多”。版本选择和前端历史恢复入口已移除，后端版本记录继续保留。

展厅工作流编辑器位于 `/workflows`，支持已确认手势触发多步展示主页/网页/视频/PPT 动作、条件与失败分支、模拟运行和步骤日志。单个手势和手势序列可选择“全局”或某个登记主页作为适用范围；同一个手势可在不同主页执行不同工作流，页面专属工作流优先于全局回退工作流，同一主页作用域内的冲突会在启用时阻止。旧工作流缺少适用主页字段时按全局处理。动作 `web.navigate_page` 可在 `promo`（企业宣传片）、`factory`（智能制造模板）、`product`（产品中心模板）之间切换；页面切换只替换 Display Shell 内部 iframe，外层 `/ws/display` 与 `/ws/events` 保持连接。新页面必须先向 Shell 确认 ready，工作流才会继续。编辑器另提供手势指针模式：主控锁定后，伸出食指移动光标，捏合并移动可拖动工作流节点，松开释放；后端使用 One Euro Filter 平滑指针，并要求默认连续 2 帧确认捏合按下和释放。前端支持四角透视校准、浏览器本地保存校准矩阵与镜像偏好、缩放/滚动坐标转换和节点内部抓取偏移。捏合按下/释放边沿不会被动画帧合并丢弃；拖动时只更新当前节点及与之相连的连线。工具栏提供指针诊断面板和 JSON 性能报告导出；仅控制本项目工作流画布，不模拟 Windows 系统鼠标。指针参数通过本机 `/api/pointer/settings` 接口读取和保存。协议、节点参数及媒体/PPT 白名单配置见 [WORKFLOWS.md](WORKFLOWS.md)。

比耶（V）手势专用于主控锁定，不再作为普通播放器动作。

默认播放器映射：

| 手势 | 动作 |
| --- | --- |
| 张开手掌 | 播放 / 暂停 |
| 竖拇指 | 音量增加 |
| 拇指向下 | 音量降低 |
| V 字手势 | 主控锁定（不触发播放器动作） |
| 握拳、食指向上、我爱你手势 | 不执行 |

全屏只能由首页上的全屏按钮触发，这是浏览器对全屏 API 的安全限制；WebSocket 手势事件不能直接请求全屏。

## AI 自动生成工作流

工作流编辑器提供“AI 生成”入口，可上传业务流程文档并自动生成节点与连线。首次运行 `.\\setup.ps1` 时，安装脚本会在项目根目录不存在 `.env` 的情况下，从 `.env.example` 创建本地配置文件。也可以直接在 `/workflows` 的 AI 生成弹窗中配置模型服务：填写 API Key、API Base URL、模型名称，选择自动兼容、Chat Completions 或 Responses 协议，并先测试连接。

默认 OpenAI 配置示例：

```dotenv
OPENAI_API_KEY=你的_API_Key
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=gpt-4o-mini
OPENAI_API_PROTOCOL=auto
```

使用中转站时，将 `OPENAI_BASE_URL` 替换为中转站提供的兼容接口根地址，将 `OPENAI_MODEL` 改为中转站支持的模型 ID。自动兼容模式优先使用 Chat Completions；若服务商不支持该接口路径，则尝试 Responses。若不支持 JSON Schema，会降级为 JSON Object 或普通 JSON 提示。API Key 只保存在本机被 Git 忽略的 `.env` 文件中；不要把密钥提交到仓库。API 调用费用按所选服务商账户用量计费，不包含在 ChatGPT 订阅中。

使用步骤：

1. 打开 `/workflows`，点击“AI 生成”。
2. 上传 PDF、DOCX、TXT 或 Markdown 文档（单个文件不超过 5 MB）；扫描版 PDF 暂不支持 OCR。
3. 选择默认启动手势，并填写补充要求，例如“播放宣传片结束后跳转到公司简介，再等待访客选择产品”。
4. 点击“解析并生成草稿”。系统提取正文后，结合当前已注册动作、动作参数规则和 SQLite 中已登记的展示页面，通过已配置的 OpenAI 兼容模型服务生成工作流结构。
5. 查看摘要、校验错误、生成假设和待确认问题。点击“应用到画布”后，生成结果只进入当前页面的未保存草稿；检查参数、连线和页面跳转，运行校验与模拟，最后手动点击“保存”。
6. 只有在保存后，才会创建工作流记录。生成过程不会自动保存、启用或执行工作流。

生成器只允许引用项目已注册动作和已登记页面 ID，不会接收模型生成的任意 URL、文件路径或代码。生成结果还会经过现有 WorkflowEngine 校验；本地页面控制动作不能接在外部网页导航之后，除非先返回本地展示主页。节点数量上限为 30，连线数量上限为 60。模型配置缺失、文件格式错误、文档过大和模型服务错误都会返回可读提示。

**文档隐私：** 上传文档正文会发送到你配置的模型服务商进行分析；文件本身不会写入项目磁盘或数据库。不要上传未经授权的商业秘密、个人信息或涉密资料。API Key 由用户自行提供和管理。

本机接口：
- `GET /api/workflow-generator/status`：检查模型配置和上传限制，不返回 API Key。
- `PUT /api/workflow-generator/config`：保存 API Key、Base URL、模型名称和接口协议。
- `POST /api/workflow-generator/test`：测试当前表单中的模型连接，不会自动保存配置。
- `POST /api/workflows/generate`：以 multipart/form-data 上传 `file`，可选 `instructions` 和 `preferred_trigger`；返回未保存工作流草稿、校验结果、警告和待确认问题。

## 增加展示主页

新增展示页面时，在 `web/pages/` 创建本地 HTML 文件，并在 `app/display_pages.py` 的 `DISPLAY_PAGES` 白名单中登记唯一 ID、标题、说明和 `/static/pages/...` 路径。页面加载 `/static/display-page.js` 并设置对应的 `data-page-id` 后，即可使用通用展示文本/面板动作。重启服务后，新 ID 会自动出现在工作流的 `web.navigate_page` 动作参数下拉框中；无需修改工作流编辑器，也不需要修改 Display Shell。自定义页面动作需遵循同源 `postMessage` 页面桥协议。不要登记外部 URL 或任意用户输入路径。

## 本机接口

- GET /：常驻 Display Shell，默认加载登记的 promo 页面。
- GET /api/display/pages：读取展示主页白名单（promo / factory / product）。
- GET /static/pages/{page}.html：提供登记的本地展示页面。
- GET /settings：RTSP 与手势映射设置页。
- GET /workflows：展厅工作流编辑器。
- GET /media/promo.mp4：宣传片，支持 HTTP Range 分段读取和 seek。
- GET /video.mjpg：最新摄像头预览 MJPEG 画面；AI 推理独立处理容量为 1 的最新帧队列。
- GET /api/status：流状态、人体轨迹及主控状态。
- POST /api/stream/start、POST /api/stream/stop：启动或停止单路 RTSP。
- POST /api/controller/unlock：解除当前主控。
- GET /api/mappings、PUT /api/mappings：读取或保存手势动作映射。
- GET /api/recognition-settings、PUT /api/recognition-settings：读取或实时修改并保存手势分类置信度门槛。
- /ws/events：推送主控状态、稳定手势和手势指针事件。
- GET /api/pointer/mode、POST /api/pointer/mode：读取和开关手势指针模式。
- GET /api/pointer/settings、PUT /api/pointer/settings：读取和持久化 One Euro 滤波、捏合阈值、稳定帧数、更新频率及手部丢失宽限参数。
- /ws/display：Display Shell 唯一动作执行通道，按 command_id 确认；切换 iframe 展示主页时保持连接。

## 数据与隐私

- 服务默认只绑定 127.0.0.1，不开放局域网或公网访问。
- RTSP 地址和凭证只交给当前运行进程处理，不保存到数据库或日志；设置页连接成功后会清空地址输入框。
- SQLite 存储手势映射、手势分类置信度门槛和手势指针参数；锁定状态和手势事件仍限于当前会话。视频与逐帧跟踪状态不持久化；服务启动、停止流或新建流会清理临时记录。
- 不使用人脸识别或外观重识别。
- 从旧版本升级时，原始“切换开关”“数值加/减”“重置”映射会迁移为播放/暂停、音量增/减和不执行；V 字手势现在专用于主控锁定，旧有 V 字播放器映射会自动迁移为“不执行”。

## 模型许可与排查

本目录可以直接作为 ZIP 解压后的项目使用，不要求 Git 仓库。若目录没有 `.git`，不要执行下文旧说明中的 `git fetch`、`git switch`，直接运行 Python 诊断命令即可；诊断图片和报告只保存在本机。

MediaPipe 模型来源和 SHA-256 清单见 MODEL_SOURCES.md。模型由安装脚本下载，不随源码提交。缺少模型时重新运行 .\setup.ps1。无法连接 RTSP 时，检查摄像头地址、账号密码、网络路由以及摄像头 RTSP 是否已启用。

RTSP 花屏和性能定位工具：在 PowerShell 中切换到项目目录后，执行 `.\.venv\Scripts\python.exe scripts\diagnose_rtsp.py --frames 120 --samples 8 --with-vision`。工具会隐藏输入 RTSP 地址，不会把地址或凭证写入报告；会保存 PyAV 原始 BGR PNG、JPEG 编码再解码后的 PNG，以及包含 FFmpeg 版本、编码格式、像素格式、帧 plane 步长、NumPy strides、连续性、预处理、Pose、Gesture、人体轨迹关联、完整视觉处理和 JPEG 编码的 median/P95 耗时。可通过 `--max-inference-width {640,720,960}`、`--num-poses {1,3,5}` 和 `--num-hands {2,4,10}` 选择参数组；分别执行 27 组并保持相同摄像头、光照、距离和动作，才能比较真实场景速度。程序默认值继续使用 960px、5 人、10 手，直到真实画面验证表明其他组合更合适。可选 `--discard-corrupt` 用于比较 FFmpeg 损坏包丢弃开关；默认保持当前解码选项。诊断图片和报告只保存在本机。

摄像头预览花屏时，先用 VLC 打开同一个 RTSP 地址：若 VLC 也花屏，优先在摄像头端切换为 H.264，关闭 H.265+/智能编码/SVC，并尝试使用 720p 或 1080p、15～20 FPS 的子码流；关键帧间隔建议设为 1～2 秒。若 VLC 正常而本项目花屏，请保留摄像头编码、分辨率和帧率信息用于进一步排查。项目使用 PyAV/FFmpeg 在 Python 进程内通过 TCP 解码 RTSP，启用损坏数据包丢弃，并跳过 FFmpeg 标记损坏或无法转换的帧。单帧视觉推理异常会被跳过；连续 3 帧处理失败时，系统会重新初始化解码器和识别模型。地址打不开、连续坏帧或读取超时会按 1、2、4、8、10 秒间隔重连；断线立即暂停控制，恢复后建立新的跟踪会话，必须重新做比耶手势。状态接口提供当前帧序号、最后一帧时间、帧新鲜度、解码器名称和重连计数。
预览 JPEG 在解码线程中独立更新，视觉模型不会阻塞画面刷新；同一容量为 1 的队列只保留最新待处理 AI 帧。当推理速度低于摄像头帧率时，队列覆盖旧帧并记录丢弃数量，避免延迟持续增长。设置页显示预览 FPS、AI 处理 FPS、预处理/模型/跟踪/完整视觉耗时、JPEG 编码耗时、队列等待及丢帧数。人体框和手部骨架以归一化坐标叠加，只在视觉结果与预览帧差距较小时显示，避免严重错位。该机制优先保证实时性，不替代对原始 PNG 的视觉检查。

宣传片主页的摄像头画中画以 `/api/status` 的 `frame_fresh` 作为显示依据，不再依赖持续打开的 multipart MJPEG 图片触发浏览器 `load` 事件或提供 intrinsic size；浏览器可能不会按普通静态图片的方式派发这些信号。MJPEG 每个 JPEG part 显式带 `Content-Length`，并设置 `X-Accel-Buffering: no`，降低分帧解析和代理缓冲风险。设置页视频下方会显示人体轨迹、检测到的手、MediaPipe 手势类别和置信度、比耶几何判断原因、关联到的人体轨迹、锁定帧进度及普通手势动作/未触发原因。手势骨架叠加在摄像头画面上。人体手腕关联不唯一时不会退回人体框猜测；只有没有有效手腕候选时，才允许使用唯一命中人体框的辅助关联。半身画面要求双肩都清晰可见；髋部在画面外不再阻止人体跟踪。

# 康晋电气大屏宣传片与手势控制

本机运行的 RTSP 手势控制展示页。首页以康晋电气宣传片为主画面，摄像头画面显示在右上角；连接地址、人体轨迹和手势映射放在独立设置页，不影响大屏展示。

## 环境与安装

- Windows 10/11 64 位
- 64 位 CPython 3.10、3.11 或 3.12；当前锁定的 NumPy/MediaPipe 组合不支持 Python 3.13/3.14
- 可访问的 RTSP 摄像头地址
- 首次安装需要联网安装依赖并下载 MediaPipe 模型；RTSP 解码使用 PyAV/FFmpeg 库并在进程内运行

在 PowerShell 中进入项目目录后运行：

~~~powershell
Set-ExecutionPolicy -Scope Process Bypass
.\setup.ps1
.\run.ps1
~~~

Python Launcher 找不到兼容解释器时，可指定已安装的解释器：

~~~powershell
.\setup.ps1 -PythonPath "C:\Python311\python.exe"
~~~

服务仅绑定本机 127.0.0.1。run.ps1 默认使用 8000 端口，若该端口已占用会自动选择下一个空闲端口，并在终端打印实际地址；停止服务按 Ctrl+C。项目使用 Python 原生提供的页面，不需要 Node.js。

## 宣传片文件

本地宣传片路径为 media/company-promo.mp4，浏览器通过支持 HTTP Range 的 /media/promo.mp4 分段读取。原始 4K 文件不转码。视频因体积较大已加入 Git 忽略规则，不会随 Git 提交；迁移整个项目文件夹时应一并保留 media/company-promo.mp4。若从 Git 单独克隆项目，请将宣传片复制到该路径，否则首页会提示视频文件不可用。

## 使用

1. 在首页点击“开始播放”，视频随后带声音循环播放。视频底部提供浏览器原生播放器控件，可用鼠标播放/暂停、拖动进度、调节音量、静音和全屏。播放器按完整 16:9 画面显示，不裁切画面中的字幕。
2. 点击右上角齿轮进入设置页；设置页在当前标签打开，使用浏览器返回或“返回大屏”回到主页。填写 rtsp:// 或 rtsps:// 摄像头地址并连接；连接后设置页显示实时画面与人体轨迹，主页右上角同步显示摄像头。
3. 主控人面向摄像头做比耶（V）手势：食指和中指伸展、无名指和小指弯曲。最近 5 帧中至少 2 帧识别成功，且始终唯一关联到同一个人体轨迹后锁定；短暂漏检可容忍，但多人候选或关联歧义不会锁定。未锁定时，手部识别最高使用 1600px 输入宽度；锁定后恢复 960px 常规输入，以兼顾远距离锁定能力和后续控制延迟。
4. 锁定后系统分配会话内稳定的 `controller_id`，并绑定当前人体 `track_id`。原轨迹短暂漏检时进入 `suspect`，立即暂停新手势动作；持续 800ms 后进入 `reacquiring`，最多保留 4 秒恢复窗口。原 `track_id` 返回时自动恢复；若跟踪器生成新 ID，仅在新轨迹首次出现时间、位置预测、躯干关键点形状和唯一性均通过严格检查时才允许重绑定。匹配有歧义时不猜测，超时自动解锁。可在设置页手动解除主控。
5. 锁定后的普通手势须连续稳定至少 3 帧、分类置信度不低于设置门槛才触发；默认门槛为 0.60，可在设置页按 0.05 步长调整至 0.50～0.90，修改后立即应用并持久化；相同动作仍有 800 ms 冷却。该置信度滑块不影响比耶主控锁定。设置页可修改其他手势映射并保存。
6. 浏览器控制台输出 [gesture-control] 事件对象，包含临时 track_id、手势类别、置信度、左右手、时间戳、动作和 21 个归一化手部关键点。

展厅工作流编辑器位于 `/workflows`，支持已确认手势触发多步网页/视频/PPT 动作、条件与失败分支、模拟运行和步骤日志。编辑器另提供手势指针模式：主控锁定后，伸出食指移动光标，捏合并移动可拖动工作流节点，松开释放；仅控制本项目工作流画布，不模拟 Windows 系统鼠标。协议、节点参数及媒体/PPT 白名单配置见 [WORKFLOWS.md](WORKFLOWS.md)。

比耶（V）手势专用于主控锁定，不再作为普通播放器动作；设置页中该项不可映射。

默认播放器映射：

| 手势 | 动作 |
| --- | --- |
| 张开手掌 | 播放 / 暂停 |
| 竖拇指 | 音量增加 |
| 拇指向下 | 音量降低 |
| V 字手势 | 主控锁定（不触发播放器动作） |
| 握拳、食指向上、我爱你手势 | 不执行 |

全屏只能由首页上的全屏按钮触发，这是浏览器对全屏 API 的安全限制；WebSocket 手势事件不能直接请求全屏。

## 本机接口

- GET /：大屏宣传片主页。
- GET /settings：RTSP 与手势映射设置页。
- GET /workflows：展厅工作流编辑器。
- GET /media/promo.mp4：宣传片，支持 HTTP Range 分段读取和 seek。
- GET /video.mjpg：最新摄像头预览 MJPEG 画面；AI 推理独立处理容量为 1 的最新帧队列。
- GET /api/status：流状态、人体轨迹及主控状态。
- POST /api/stream/start、POST /api/stream/stop：启动或停止单路 RTSP。
- POST /api/controller/unlock：解除当前主控。
- GET /api/mappings、PUT /api/mappings：读取或保存手势动作映射。
- GET /api/recognition-settings、PUT /api/recognition-settings：读取或实时修改并保存手势分类置信度门槛。
- /ws/events：推送主控状态、稳定手势和手势指针事件。
- GET /api/pointer/mode、POST /api/pointer/mode：读取和开关手势指针模式。
- /ws/display：主页唯一动作执行通道，按 command_id 确认。

## 数据与隐私

- 服务默认只绑定 127.0.0.1，不开放局域网或公网访问。
- RTSP 地址和凭证只交给当前运行进程处理，不保存到数据库或日志；设置页连接成功后会清空地址输入框。
- SQLite 存储手势映射与手势分类置信度门槛；锁定状态和手势事件仍限于当前会话。视频与逐帧跟踪状态不持久化；服务启动、停止流或新建流会清理临时记录。
- 不使用人脸识别或外观重识别。阶段一的跨 Track ID 恢复仅使用位置预测、人体框尺度和 Pose 躯干关键点几何；它不是行人 ReID，遇到多人相似或遮挡歧义时会拒绝自动重绑定。
- 从旧版本升级时，原始“切换开关”“数值加/减”“重置”映射会迁移为播放/暂停、音量增/减和不执行；V 字手势现在专用于主控锁定，旧有 V 字播放器映射会自动迁移为“不执行”。

## 模型许可与排查

本目录可以直接作为 ZIP 解压后的项目使用，不要求 Git 仓库。若目录没有 `.git`，不要执行下文旧说明中的 `git fetch`、`git switch`，直接运行 Python 诊断命令即可；诊断图片和报告只保存在本机。

MediaPipe 模型来源和 SHA-256 清单见 MODEL_SOURCES.md。模型由安装脚本下载，不随源码提交。缺少模型时重新运行 .\setup.ps1。无法连接 RTSP 时，检查摄像头地址、账号密码、网络路由以及摄像头 RTSP 是否已启用。

RTSP 花屏和性能定位工具：在 PowerShell 中切换到项目目录后，执行 `.\.venv\Scripts\python.exe scripts\diagnose_rtsp.py --frames 120 --samples 8 --with-vision`。工具会隐藏输入 RTSP 地址，不会把地址或凭证写入报告；会保存 PyAV 原始 BGR PNG、JPEG 编码再解码后的 PNG，以及包含 FFmpeg 版本、编码格式、像素格式、帧 plane 步长、NumPy strides、连续性、预处理、Pose、Gesture、人体轨迹关联、完整视觉处理和 JPEG 编码的 median/P95 耗时。可通过 `--max-inference-width {640,720,960}`、`--num-poses {1,3,5}` 和 `--num-hands {2,4,10}` 选择参数组；分别执行 27 组并保持相同摄像头、光照、距离和动作，才能比较真实场景速度。程序默认值继续使用 960px、5 人、10 手，直到真实画面验证表明其他组合更合适。可选 `--discard-corrupt` 用于比较 FFmpeg 损坏包丢弃开关；默认保持当前解码选项。诊断图片和报告只保存在本机。

摄像头预览花屏时，先用 VLC 打开同一个 RTSP 地址：若 VLC 也花屏，优先在摄像头端切换为 H.264，关闭 H.265+/智能编码/SVC，并尝试使用 720p 或 1080p、15～20 FPS 的子码流；关键帧间隔建议设为 1～2 秒。若 VLC 正常而本项目花屏，请保留摄像头编码、分辨率和帧率信息用于进一步排查。项目使用 PyAV/FFmpeg 在 Python 进程内通过 TCP 解码 RTSP，启用损坏数据包丢弃，并跳过 FFmpeg 标记损坏或无法转换的帧。单帧视觉推理异常会被跳过；连续 3 帧处理失败时，系统会重新初始化解码器和识别模型。地址打不开、连续坏帧或读取超时会按 1、2、4、8、10 秒间隔重连；断线立即暂停控制，恢复后建立新的跟踪会话，必须重新做比耶手势。状态接口提供当前帧序号、最后一帧时间、帧新鲜度、解码器名称和重连计数。
预览 JPEG 在解码线程中独立更新，视觉模型不会阻塞画面刷新；同一容量为 1 的队列只保留最新待处理 AI 帧。当推理速度低于摄像头帧率时，队列覆盖旧帧并记录丢弃数量，避免延迟持续增长。设置页显示预览 FPS、AI 处理 FPS、预处理/模型/跟踪/完整视觉耗时、JPEG 编码耗时、队列等待及丢帧数。人体框和手部骨架以归一化坐标叠加，只在视觉结果与预览帧差距较小时显示，避免严重错位。该机制优先保证实时性，不替代对原始 PNG 的视觉检查。

宣传片主页的摄像头画中画以 `/api/status` 的 `frame_fresh` 作为显示依据，不再依赖持续打开的 multipart MJPEG 图片触发浏览器 `load` 事件或提供 intrinsic size；浏览器可能不会按普通静态图片的方式派发这些信号。MJPEG 每个 JPEG part 显式带 `Content-Length`，并设置 `X-Accel-Buffering: no`，降低分帧解析和代理缓冲风险。设置页视频下方会显示人体轨迹、检测到的手、MediaPipe 手势类别和置信度、比耶几何判断原因、关联到的人体轨迹、锁定帧进度及普通手势动作/未触发原因。手势骨架叠加在摄像头画面上。人体手腕关联不唯一时不会退回人体框猜测；只有没有有效手腕候选时，才允许使用唯一命中人体框的辅助关联。半身画面要求双肩都清晰可见；髋部在画面外不再阻止人体跟踪。
